# v0.0.4

## Fixes

- Images refresh after a pull changes the design, even when Figma keeps
  the same version ID. Snapshot updates and cache eviction now commit
  together, so an interrupted pull cannot leave new nodes with old images.
- `serve` keeps answering reads during background pulls. Busy request
  queues no longer block watch sync, and explicit syncs preserve pending
  metadata retries.
- Pulls validate replacement data before clearing an existing mirror.
  Malformed document trees and unsafe stored file keys fail before they
  can damage the mirror.
- REST requests and image downloads have time and size limits. CLI mirror
  directories reject unsafe paths and use private permissions.
- Imports accept trees deeper than 63 node levels. Variable bindings work
  with property names that contain `/` or `~`.
- Search results keep the same order when scores tie. `at` requires a
  page and limits its output. CLI reads honor file selection and node URLs.
- Desktop tool calls keep their original arguments and results across
  direct and socket-routed CLI calls. figmog forwards these calls without
  caching them.
- `figmog --db <store> images` and explicit-store servers can export
  verified cached renders and image fills without a token or file key.

## Variable imports

`import-variables` now replaces the previous variable snapshot. It removes
variables and collections missing from the new export. Use `--dry-run` to
preview the changes. Replacing stored variables with an empty export
requires `--allow-empty`.

Invalid imports leave the previous snapshot untouched. `vars --snapshot`
and `status` report the snapshot's source and counts, including stores
that have imported variables but have never pulled a file. Variable rows
include code names and publishing flags. Enterprise pulls count changes
to those fields in their churn output.

## Upgrading

Existing mirrors remain readable. You do not need to rebuild them.

- Install the new binary and restart running `figmog serve` processes.
  Restart them after credential changes too. If you use `FIGMA_TOKEN`,
  start the server with the updated environment.
- Older cached renders need a fresh download through a file-keyed mirror
  before this build can export them. That request requires credentials
  and spends API budget again. An explicit `--db` store cannot fetch
  replacements without a file key.
- `figmog_open` and `figmog_sync` return background job acknowledgements.
  Poll `figmog_status` for readiness, progress and errors.
- Run `figmog version` to check which version a binary reports.

## Rendering limits

Figma can return different live contents under the same version ID.
Passing that ID to the render endpoint does not freeze every edit. A
cache miss can return a later edit or fail for a node deleted after the
pull. Historical renders of those nodes are not guaranteed.

## Downloads

The release workflow publishes testing archives for
`aarch64-apple-darwin`, `x86_64-apple-darwin` and
`x86_64-unknown-linux-gnu`, plus `SHA256SUMS`. See the
[installation instructions](https://github.com/net-work-studio/figmog#install).

figmog remains AGPL-3.0-only. Broader binary distribution remains deferred
under the repository's existing policy while the pinned `fold` dependency
lacks an upstream license file. See the
[license notes](https://github.com/net-work-studio/figmog#license).
